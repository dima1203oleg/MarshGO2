## Що змінилося

Збільшено обмеження додаткових зупинок на один GTFS route/direction/headsign pattern з 2 до 8. Незмінною лишилась абсолютна межа 48 зупинок на бік, а також найближчі 20 зупинок. Доданий regression test моделює корисну 21-шу зупинку на напрямку, який уже представлений двома ближчими зупинками: квота 2 втрачає прямий рейс, квота 8 його знаходить.

## Перевірка

- Вхідний статичний Львівський GTFS: 1 071 зупинка, 72 маршрути, 15 716 рейсів; ZIP SHA-256 `bb4ac0ce9127b4967ad889379f523b04b84a0bb033814aa8c844526b42078164`.
- Порівняно квоти 2 та 8 на тих самих п’яти коридорах, одному часовому вікні та Node `24.21.0`.
- При квоті 8 `stopSelectionTruncated` знято на чотирьох із п’яти коридорів. У північному коридорі до центру прапорець лишився через межу 48 зупинок. Це очікуване повідомлення про невивчені кандидати.
- Кількість повернених результатів у насичених запитах лишилася 100; на двох коридорах — 0 в обох конфігураціях. У насичених запитах набір route-name chains дещо змінився: на одному втрачено 2 і додано 1, на іншому без змін, на третьому втрачено 3 і додано 1. Це не є доказом тотожності або повноти результатів; `candidateSamplingTruncated` лишається піднятим там, де спрацював семплер.
- Часові кроки пошуку зросли на 0–12% на перевірених коридорах. Це один прогін на коридор, не статистичне latency/RSS дослідження.
- Новий regression test при квоті 2 падає саме через втрачений рейс; при квоті 8 проходить.
- На точному кандидаті Node `24.21.0`: `npm run typecheck` PASS, `npm run lint` PASS, повний unit suite **290 PASS / 0 FAIL / 3 opt-in DB/Redis integration SKIP**, `npm audit --omit=dev --audit-level=moderate` — **0 vulnerabilities**.

## Три режими ранжування

Додатково порівняно топового кандидата після ранжування тими самими production-функціями FASTEST, CHEAPEST і BALANCED на вибірках по 20 результатів для трьох насичених коридорів. При квотах 2 і 8 переможці були однакові:

| Коридор | FASTEST | CHEAPEST | BALANCED |
|---|---|---|---|
| Малоголосківська → Площа Ринок | А51, 1 744 с | А47, 2 299 с | А51, 1 744 с |
| Малоголосківська → Залізничний вокзал | А51, 2 192 с | А51, 2 192 с | А51, 2 192 с |
| Залізничний вокзал → Автовокзал | Т04 → А09, 2 900 с | Тр22, 3 324 с | Тр22, 3 324 с |

У цих прикладах показана вартість 23 грн є оцінкою з конфігурованого міського тарифу, а не ціною, повернутою live-провайдером. Однакові переможці в обмеженій вибірці підтверджують лише ці конкретні сценарії: вихідний пул і далі має `searchTruncated=true`, а отже, виграш поза ним не доведений.

## Межі висновку

Це обмежене покращення відбору зупинок, а не розв’язання повноти пошуку. Абсолютний stop cap і bounded candidate sampling усе ще можуть пропускати варіанти, тому клієнт має показувати неповний статус. Це статичний графік, не доказ поточних позицій, прибуття, цін або доступності. Staging, реальний API та production не перевірялися.

Джерело ZIP залишено лише у тимчасовому локальному аудит-середовищі; у репозиторій його не додано.
