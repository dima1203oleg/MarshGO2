# GTFS: збереження стратегій перед міжпровайдерним лімітом

Дата: 2026-10-20

## Знахідка

Після пошуку GTFS-кандидатів по окремих джерелах сервер зводив їх у загальний список, сортував лише за часом прибуття та залишав перші 100. Це відбувалося до оцінювання `FASTEST`, `CHEAPEST` та збалансованої стратегії. Через це пізніший, але дешевший маршрут міг зникнути ще до формування результатів.

## Зміна в ізольованій гілці

У Server branch `codex/gtfs-query-directed-stop-budget-20261020`, commit `c7948bd88c36e03c0a5d81ba7f4c49906e92bc5c`, stacked на PR #17 head `1a3598cc270af0d353a2b22cda740f81daa0da73`, додано обмежений детермінований відбір перед міжпровайдерним скорингом:

1. зберігаються кандидати з найменшою тривалістю;
2. зберігаються найнижчі відомі порівнювані тарифи в UAH;
3. зберігаються варіанти з найменшою кількістю пересадок і ходьби;
4. додається збалансований рейтинг;
5. вільні місця заповнюються ранніми прибуттями.

Жорсткий ліміт залишається 100. Коли кандидатів більше за ліміт, API і далі позначає результат як частковий. Невідома ціна не потрапляє в найдешевші.
